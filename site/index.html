WorkBuddy / CodeBuddy 에이전트 앞에 OAuth로 보호되는 /v1을 세웁니다. OpenAI SDK, curl, GJC가 base_url과 토큰만으로 붙고, 함수 호출은 진짜 tool_calls로 돌아옵니다.

An OAuth-protected /v1 in front of the WorkBuddy / CodeBuddy agent. OpenAI SDKs, curl and GJC connect with a base_url and a token, and function calling comes back as real tool_calls.

가이드 읽기 ↗ Read the guide ↗ GJC에 붙이기 Attach to GJC
gjc → /v1 → agent
# 1. token (one per device)
❯ node tools/get-token.mjs --name laptop > ~/.config/wb-agent-token
# 2. models.yml: provider wb-agent (openai-completions)
❯ export WB_AGENT_TOKEN="$(cat ~/.config/wb-agent-token)"
❯ gjc -p --tools=read \
    --model "wb-agent/workbuddy-minimal:gpt-5.5:high" \
    "read ./note.txt, reply with the secret word"
  toolCall read {"path":"./note.txt"}

01 / QUICK START

세 단계로 첫 호출까지

Three steps to the first call

STEP 01

에이전트와 게이트웨이 설치

Install agent and gateway

전용 사용자에 @tencent-ai/codebuddy-code와 이 레포를 설치하고, 자격증명은 .env(600)에만 둡니다.

Install @tencent-ai/codebuddy-code and this repo for a dedicated user; credentials live only in .env (600).

STEP 02

서비스로 실행

Run it as a service

toolsMode: translate, permissionMode: dontAsk로 설정하고 systemd 유닛으로 띄웁니다. 업스트림은 게이트웨이가 감시합니다.

Set toolsMode: translate and permissionMode: dontAsk, start the systemd unit; the gateway supervises the upstream.

STEP 03

토큰 발급 후 호출

Issue a token and call

tools/get-token.mjs로 기기별 토큰을 받고 /v1/chat/completions를 호출합니다.

Get a per-device token with tools/get-token.mjs and call /v1/chat/completions.

연결 전에. 게이트웨이는 서버에서 에이전트를 실행하는 엔드포인트입니다. 루프백·사설망·HTTPS 프록시 뒤에만 두고, 토큰·접속 암호·API 키·실제 주소는 Git에 넣지 마세요. bypassPermissions를 기본값으로 두면 접근 가능한 누구나 서버에서 명령을 실행할 수 있습니다.

Before you connect. The gateway runs an agent on the host. Keep it on loopback, a private network or behind an HTTPS proxy, and keep tokens, the access code, API keys and real addresses out of Git. Defaulting to bypassPermissions lets anyone who can reach it run commands on the host.
