00 / WHY

왜 이 게이트웨이인가요

Why this gateway

WorkBuddy / CodeBuddy 계정의 모델과 에이전트는 앱과 CLI 안에서만 쓰입니다. codebuddy --serve는 공유 비밀번호와 쿠키로만 열리고 OpenAI 형식도 아니라 다른 도구가 붙을 수 없습니다.

A WorkBuddy / CodeBuddy account's models and agent live inside the app and CLI. codebuddy --serve opens only with a shared password and cookie and does not speak OpenAI, so other tools cannot connect.

REUSE

가진 계정을 다른 도구에서

Your account, in other tools

OpenAI SDK, curl, GJC가 base_url과 토큰만으로 코드 수정 없이 붙습니다.

OpenAI SDKs, curl and GJC connect with a base_url and a token, unchanged.

TOKENS

기기마다 폐기 가능한 토큰

Revocable per-device tokens

공유 비밀번호 대신 범위가 정해진 OAuth 토큰을 기기별로 발급합니다.

Scoped OAuth tokens per device instead of a shared password.

TOOL_CALLS

도구는 내 컴퓨터에서

Tools run on your machine

에이전트의 판단을 진짜 tool_calls로 돌려줘 GJC가 로컬에서 실행합니다. 공급자 API 키가 있다면 직접 연결이 더 빠릅니다.

Agent decisions come back as real tool_calls for GJC to run locally. With a provider API key, a direct connection is faster.

01 / QUICK START

세 단계로 첫 호출까지

Three steps to the first call

STEP 01

에이전트와 게이트웨이 설치

Install agent and gateway

전용 사용자에 @tencent-ai/codebuddy-code와 이 레포를 설치하고, 자격증명은 .env(600)에만 둡니다.

Install @tencent-ai/codebuddy-code and this repo for a dedicated user; credentials live only in .env (600).

STEP 02

서비스로 실행

Run it as a service

toolsMode: translate, permissionMode: dontAsk로 설정하고 systemd 유닛으로 띄웁니다. 업스트림은 게이트웨이가 감시합니다.

Set toolsMode: translate and permissionMode: dontAsk, start the systemd unit; the gateway supervises the upstream.

STEP 03

토큰 발급 후 호출

Issue a token and call

tools/get-token.mjs로 기기별 토큰을 받고 /v1/chat/completions를 호출합니다.

Get a per-device token with tools/get-token.mjs and call /v1/chat/completions.

The token is referenced from the environment. Merge it into your config.

연결 전에. 게이트웨이는 서버에서 에이전트를 실행하는 엔드포인트입니다. 루프백·사설망·HTTPS 프록시 뒤에만 두고, 토큰·접속 암호·API 키·실제 주소는 Git에 넣지 마세요. agent:run 토큰 보유자는 요청으로 bypassPermissions를 지정해 서비스 사용자 권한으로 명령을 실행할 수 있으니, dontAsk 기본값을 상한으로 믿지 말고 믿는 기기에만 토큰을 발급하세요. 비공식 연동이므로 계정 약관에서 이런 사용이 허용되는지 먼저 확인하세요.

Before you connect. The gateway runs an agent on the host. Keep it on loopback, a private network or behind an HTTPS proxy, and keep tokens, the access code, API keys and real addresses out of Git. An agent:run token holder can request bypassPermissions and run commands as the service user, so do not treat the dontAsk default as a ceiling; issue tokens only to trusted devices. This is an unofficial integration: check that your account terms allow this use.
